# Evidence

Every court emits one immutable JSON receipt into `evidence/receipts/`
(schema version in `src/evidence/receipt.rs`). Receipt files embed a
content-derived run id and a SHA-256 self-hash; they are never overwritten,
and `vole-gfx evidence verify <file>` checks the self-hash.

## Receipt contents

schema_version, run_id, timestamp, git commit/dirty, command, court,
universe, profile, backend, exact flag, inputs/outputs (content-addressed),
canonical & reference hashes, quality metric/value (quality-bounded mode),
persistent/residual/fallback/index bytes, peak host/VRAM bytes, cpu/gpu/end-
to-end times, memory traffic, samples requested/evaluated, dependency count,
candidates evaluated/pruned, search time, fallback/residual fractions, pass,
unsupported_reason, notes, and a full environment snapshot (CPU model + ISA
subfeatures, GPU + driver, OS/kernel, rustc/LLVM, profile).

## Claims ledger

`evidence/claims.json` holds claims with status values:

`prior_art | proposal | hypothesis | demonstrated | weakened | falsified | unsupported`

A benchmark does not promote a claim automatically. A claim becomes
*demonstrated* only for the exact domain of its receipts; README language
follows the ledger.

## Reports (generated from receipts)

`evidence/PARETO.md`, `evidence/PERFORMANCE.md`, `evidence/INVERSE.md`,
`evidence/DIRECT_MATERIALIZATION.md`, `evidence/HARDWARE_OPERATION_MIX.md`.
Generated by the courts/seal tooling from receipts only — never hand-edited
benchmark prose.
